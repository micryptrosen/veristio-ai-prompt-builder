# AI Prompt Builder

A local reusable prompt composition builder: rough idea in, organized prompt out.

## Provenance

Written during the current official Devpost Learn 2-scope process on 2026-10-01 from actual owner responses, after the first prototype and public snapshot existed. This is current reconciliation, not original pre-build planning or proof of earlier Skill Pack usage. Approved on 2026-10-01 under the owner's explicit instruction to approve if it reflects their answers and the existing prototype; both conditions were checked. Later stages and submission eligibility remain unresolved.

## The Unique Kernel

Turn an incomplete prompt idea into an explicit, reusable instruction set by separating task, audience, context, constraints, tone and desired output. The visible structure and review checklist help the user recognize what the rough idea left unstated, without asking the app to call an AI service.

## Who It's For

An everyday professional, small business owner, educator, writer or AI beginner who knows what help they want but struggles to express it as a clear, complete prompt. Their starting point is a messy or incomplete idea rather than a reusable set of instructions.

## The Core Loop

Enter a rough goal, fill the guided fields, generate a structured prompt, review its organization and checklist, and copy it for use elsewhere. Reset to start another task. Users return when they need to organize another request.

## Inspiration & Identity

Clear, practical first screen; no decorative overbuild. This is a composition utility, distinct from Entry 01's prompting challenge. Project Designer is supporting concept evidence only, not implementation material; Book 19 remains source reference only.

## Why This Matters to the Learner

The owner wants to understand the idea-to-scope-to-PRD-to-spec-to-build-evidence handoffs when an AI coding agent implements much of the work. The practice is keeping documents grounded in real decisions, the checklist grounded in actual work, and submission provenance honest.

## What "Working" Looks Like

One end-to-end workflow: a user enters a messy or incomplete idea, supplies task, audience, context, constraints, tone and desired output format, generates an organized reusable prompt, copies it and resets. The user can identify how the explicit instructions improve on the rough input. Owner's finish line: "rough idea in, organized prompt out."

This is demonstrable on a screen; actual current owner review and anonymous hosted playback checks are now recorded in verification.md and shipping-readiness.md. Structured wording is not evidence of improved model answers or accuracy.

## The POC Boundary

One static local web app, no backend. Guided fields and a generated text prompt with a short review checklist; sample, copy/fallback and reset controls. Existing source-notes and review-focus fields remain supporting inputs. No automatic assessment of a user's understanding; owner hands-on feedback must verify that the structure/checklist makes the added clarity understandable.

## Later

No additional features committed to in this scope conversation. Record further owner requests separately instead of quietly expanding the prototype.

## Explicitly Cut

- External AI calls and generated answers: this pilot composes reusable prompts, rather than running them.
- Backend, accounts and cloud persistence: unnecessary to demonstrate the local composition loop.
- Prompt-quality scoring or guaranteed results: organization does not certify semantic quality or model performance.
- Copying private source/reference material: independent implementation and source custody remain required.
- Deployment and Devpost submission in this pilot: separate actions, not prerequisites for proving the local loop.
